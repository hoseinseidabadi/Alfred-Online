# Contract — پل لبه ⇄ هسته (Bridge API)

**Feature**: `001-request-intake-triage` · **Version**: 1.0
**مالک قرارداد**: هسته (Liara) آن را عرضه می‌کند؛ لبه (Cloudflare) مصرف‌کننده است.

> **قاعدهٔ حاکم بر این قرارداد** (اصل III): تمام تماس‌ها از سمت **لبه** آغاز می‌شوند.
> هسته هرگز تماس خروجی به خارج از کشور نمی‌گیرد. این عمدی است: ضعیف‌ترین مسیر اصلاً استفاده نمی‌شود.

**احراز هویت**: هدر `X-Bridge-Key` با راز مشترک. هر تماس بدون آن `401` می‌گیرد.
**زمان**: تمام timestamp ها ISO-8601 با منطقهٔ زمانی UTC. هیچ تاریخ جلالی در این قرارداد رد و بدل نمی‌شود.

---

## ۱. `POST /bridge/submissions` — تحویل ثبت‌های معطل

لبه ثبت‌های تحویل‌نشده را به‌ترتیب `submittedAt` می‌فرستد.

**Request**

```json
{
  "submissions": [
    {
      "requestId": "REQ-149",
      "chatId": "…",
      "submitterName": "…",
      "unit": "editorial",
      "requestType": "bug",
      "rawAnswers": {
        "where": "وب‌سایت",
        "action": "صفحهٔ خبر رو باز کردم، ساعت شلوغی عصر",
        "observed": "خطای 502 داد",
        "since": "this_week",
        "scope": "few_people",
        "roleQuestion": "…"
      },
      "attachments": [{ "kind": "photo", "ref": "…" }],
      "submittedAt": "2026-08-24T06:44:00Z"
    }
  ]
}
```

**Response `200`**

```json
{ "accepted": ["REQ-149"], "rejected": [] }
```

**قواعد**

- **Idempotent روی `requestId`.** ارسال دوباره MUST رکورد تکراری نسازد و MUST همان `accepted` را برگرداند.
- هسته MUST NOT `rawAnswers` را تغییر دهد یا نرمال‌سازی کند (اصل II).
- هسته MUST `responseDueAt = submittedAt + 7d` را خودش محاسبه کند.
- خطای `5xx` یا عدم پاسخ → لبه رکورد را در صف نگه می‌دارد و بعداً تلاش می‌کند. **هیچ ثبتی حذف نمی‌شود.**
- ترتیب MUST حفظ شود؛ اگر یک قلم رد شد، بقیه همچنان پردازش می‌شوند و در `rejected` گزارش می‌گردند.

## ۲. `GET /bridge/outbound` — دریافت پاسخ‌های آمادهٔ ارسال

لبه پاسخ‌های تأییدشده‌ای را که هنوز به کاربر نرسیده‌اند می‌کشد.

**Response `200`**

```json
{
  "responses": [
    {
      "responseId": "RSP-0312",
      "requestId": "REQ-149",
      "chatId": "…",
      "body": "REQ-149 — بررسی شد ✅\n\nاین باگ را در خرداد …",
      "approvedAt": "2026-08-25T07:10:00Z"
    }
  ]
}
```

**قواعد**

- هسته MUST NOT پاسخی را که `approvedBy` ندارد در این خروجی بگذارد (FR-033).
- متن `body` **آماده و نهایی** است؛ لبه MUST NOT آن را بازنویسی یا خلاصه کند.
- تا وقتی تأییدیهٔ بند ۳ نرسیده، هسته MUST همان پاسخ را دوباره برگرداند.

---

## ۳. `POST /bridge/outbound/ack` — تأیید تحویل به کاربر

```json
{ "delivered": [{ "responseId": "RSP-0312", "sentAt": "2026-08-25T07:11:04Z" }] }
```

**قاعده**: تنها پس از این تماس، هسته `Response.deliveredAt` را پر می‌کند و `Request` قابل بستن می‌شود.

---

## ۴. `GET /bridge/access/{chatId}` — استثناهای دسترسی _(اختیاری)_

```json
{ "chatId": "…", "accessStatus": "exception" }
```

**قاعده**: منبع اصلی دسترسی، عضویت کانال است که در **لبه** بررسی می‌شود (R-05).
این نقطهٔ تماس فقط استثناهای دستی (FR-002) را می‌دهد و اگر در دسترس نبود،
لبه MUST به بررسی عضویت اکتفا کند و ثبت را متوقف نکند.

---

## ۵. `GET /bridge/health` — سلامت پل

```json
{ "ok": true, "coreTime": "2026-08-25T07:11:00Z" }
```

لبه نتیجهٔ آخرین تماس‌ها را نگه می‌دارد تا هسته بتواند وضعیت پل و تعداد اقلام معطل در هر
جهت را نمایش دهد (FR-019).

## رفتار در قطعی — قلب این قرارداد

| وضعیت                   | رفتار لبه                                        | آنچه کاربر می‌بیند    |
| ----------------------- | ------------------------------------------------ | --------------------- |
| هسته `5xx` می‌دهد       | نگه‌داشتن در صف، تلاش با عقب‌نشینی نمایی         | **هیچ**               |
| هسته اصلاً پاسخ نمی‌دهد | همان                                             | **هیچ**               |
| قطعی چند روزه           | صف انباشته می‌شود؛ ثبت جدید همچنان شماره می‌گیرد | **هیچ**               |
| بازگشت ارتباط           | تحویل به‌ترتیب زمانی، idempotent                 | پاسخ‌های معطل می‌رسند |

**آزمون الزامی ۳ و SC-004 مستقیماً همین جدول را می‌سنجند.**
