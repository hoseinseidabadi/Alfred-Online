## راه‌اندازی محلی

```bash
# ریشهٔ ریپو
npm install

# هسته — نیازمند PostgreSQL محلی
cp apps/core/.env.example apps/core/.env      # DATABASE_URL, BRIDGE_KEY, SESSION_SECRET
npm run -w apps/core migrate
npm run -w apps/core dev                       # http://localhost:3001

# داشبورد
npm run -w apps/dashboard dev                  # http://localhost:3000

# لبه — با زمان اجرای محلی Workers
cp apps/edge/.dev.vars.example apps/edge/.dev.vars   # TELEGRAM_TOKEN, WEBHOOK_SECRET, BRIDGE_KEY, CORE_URL
npm run -w apps/edge dev
```

**اسرار هرگز در ریپو نمی‌روند** — فقط `.env` / `.dev.vars` محلی، و Secret Store هر دو محیط در
استقرار (اصل «اسرار و دسترسی»).

**دادهٔ نمونه**: `npm run seed` — چند درخواست، یک صف، و دو مایلستون می‌سازد تا داشبورد خالی نباشد.

## سناریوهای اعتبارسنجی

هر سناریو به داستان کاربر و معیار موفقیت متناظرش نگاشت شده. **این‌ها همان چیزی هستند که
«کار می‌کند» را تعریف می‌کنند.**

### V-1 — ثبت کامل (US1 · SC-002)

1. از یک حساب تلگرام که عضو کانال است، گفت‌وگو را شروع کن.
2. نوع «باگ» را انتخاب کن و پنج سوال را جواب بده.
3. **انتظار**: شمارهٔ `REQ-NNN` و پیام تعهد هفت‌روزه دریافت می‌شود؛ کل کار زیر سه دقیقه.
4. **انتظار**: در دیتابیس هسته، `rawAnswers` **عیناً** همان متن فارسی است.

### V-2 — واحد فقط یک بار پرسیده می‌شود (US1 · FR-003)

ثبت دوم با همان حساب → **انتظار**: سوال واحد سازمانی پرسیده **نمی‌شود**.

### V-3 — غیرعضو (US1 · FR-001)

از حسابی که عضو کانال نیست تلاش کن → **انتظار**: ثبت انجام نمی‌شود؛ پیام راهنما می‌آید.

### V-4 — ✅ ثبت با هستهٔ خاموش (US1 · FR-015 · **آزمون الزامی ۱**)

1. هسته را متوقف کن.
2. یک ثبت کامل انجام بده.
3. **انتظار**: شماره صادر می‌شود و کاربر **هیچ تفاوتی** حس نمی‌کند.
4. **انتظار**: رکورد در D1 لبه با `deliveredToCoreAt = null`.

### V-5 — ✅ بازگشت ارتباط (FR-017 · **آزمون الزامی ۳**)

1. با هستهٔ خاموش، سه ثبت انجام بده.
2. هسته را روشن کن و منتظر یک چرخهٔ Cron بمان.
3. **انتظار**: هر سه، **به‌ترتیب زمانی** و بدون تکرار در هسته ظاهر می‌شوند.
4. اجرای دوبارهٔ Cron → **انتظار**: هیچ رکورد تکراری (idempotency).

### V-6 — ✅ بقای گفت‌وگو (FR-014 · **آزمون الزامی ۴**)

وسط سوال سوم، لبه را ری‌استارت کن → **انتظار**: کاربر از همان سوال ادامه می‌دهد.

### V-7 — ✅ یکتایی شماره (FR-016 · **آزمون الزامی ۲**)

چند ثبت هم‌زمان + ری‌استارت لبه → **انتظار**: هیچ شمارهٔ تکراری، هیچ شکاف پرش‌دار.

### V-8 — ✅ هشدار پیش از نقض تعهد (FR-030 · **آزمون الزامی ۵**)

ثبتی با `submittedAt` شش روز پیش بساز → **انتظار**: در بستهٔ تریاژ `atRisk = true` است،
**پیش از** رسیدن به روز هفتم.

### V-9 — تریاژ و پاسخ (US2 · SC-001)

1. `GET /api/triage/batch` → **انتظار**: پاسخ‌های خام، مهلت، پیشنهاد سرویس، و تصویر صف.
2. تصمیم `reject` بدون یکی از سه بخش بفرست → **انتظار**: `422 REJECT_INCOMPLETE`.
3. تصمیم بدون `approvedBy` → **انتظار**: `422 APPROVAL_REQUIRED`.
4. تصمیم کامل → **انتظار**: `RSP-NNNN` ساخته و پس از یک چرخه در تلگرام تحویل می‌شود.

### V-10 — تغییر نوع بدون تغییر شماره (FR-021)

نوع را از `bug` به `improvement` عوض کن → **انتظار**: `id` ثابت؛ ردیف `AuditEntry` ساخته می‌شود.

### V-11 — ✅ قطعی ۷۲ ساعته (**SC-004** — آزمون اجراشدنی الزامی)

با زمان جهش‌داده‌شده: ۷۲ ساعت قطعی، N ثبت در طول آن، سپس اتصال.
**انتظار**: `N` ثبت رسیده، صفر گم‌شده، ترتیب حفظ‌شده، صفر تکراری.

### V-12 — هزینهٔ فرصت مرئی (US4 · FR-037 · SC-005)

آیتمی را در موقعیت ۱ درج کن → **انتظار**: `displaced` فهرست آیتم‌های عقب‌افتاده و روزهای تأخیر
را برمی‌گرداند، و مایلستون وابسته `at_risk` می‌شود با `riskReason` اشاره‌کننده به همان آیتم.

### V-13 — قاعدهٔ سه کارت (US3 · FR-039)

جلسه‌ای با دو کارت ثبت کن → **انتظار**: `422 MIN_THREE_CARDS`.

### V-14 — مسیر سریع (US5 · FR-042، FR-043)

1. تصمیم `fast_track` بدون متریک و تاریخ بازبینی بفرست.
2. **انتظار**: **پذیرفته می‌شود** و آیتم بلافاصله `in_progress` می‌شود — اجرا مسدود نمی‌شود.
3. **انتظار**: رکورد `incomplete` علامت می‌خورد و پس از ۴۸ ساعت در هشدارها ظاهر می‌شود.
4. همان درخواست با `forum = council` و بدون متریک → **انتظار**: `422 METRIC_AND_REVIEW_REQUIRED`.

### V-15 — داشبورد در سی ثانیه (US3 · SC-003)

داشبورد را به کسی که ندیده نشان بده و بپرس: چند مورد بحرانی باز است؟ قدیمی‌ترین چند روزه است؟
از تعهد عقبیم؟ → **انتظار**: هر سه، زیر سی ثانیه، بدون راهنمایی.

### V-16 — خروجی آفلاین (FR-050)

snapshot بگیر، شبکه را قطع کن، فایل را باز کن → **انتظار**: همان محتوا، بدون درخواست بیرونی.

### V-17 — زبان و تقویم (اصل «زبان و تقویم»)

هر صفحه و هر پیام → **انتظار**: فارسی، تقویم جلالی، ساعت تهران. **هیچ تاریخ میلادی و هیچ عدد
تحلیلی داخلی (امتیاز، شدت) به ثبت‌کننده نشان داده نمی‌شود.**

### V-18 — مخزن دانش فقط‌خواندنی (اصل I · FR-052، FR-055)

1. کل چرخه را با مخزن دانش **غیرقابل‌دسترس** اجرا کن → **انتظار**: ثبت و پاسخ‌گویی کار می‌کند.
2. `git status` مخزن دانش پس از یک چرخهٔ کامل → **انتظار**: **دست‌نخورده**.
